# 星海会馆、星图位阶与人机练习

## 已实现的入口

主页「星海会馆」或顶部「联机」打开服务器大厅。顶部「练习」进入机巧练武庭，离线可用，不受收集进度限制。

在「服务器与昵称」填写 HTTP(S) 或 WS(S) 地址。地址自动补全 `/ws`，支持反向代理子路径，例如 `https://example.com/tactics` 对应 `wss://example.com/tactics/ws`。保存并测试会建立真实 WebSocket、执行协议握手并读取真实房间；不会用演示数据伪装在线房间。

「创建棋局」可以填写 24 字以内名称、160 字以内简介，选择休闲或排位。公共基础卡池让双方从相同完整卡池开始选卡，无战役等级与遗物加成。房主可在等待时修改名称、简介；来客准备后，由房主开始。房间列表实时更新，也可用房间码直接加入。

局内操作由服务器验证。联机选卡每手 45 秒、部署每方 90 秒、行动回合 120 秒；超时分别自动选首张候选、补齐部署或结束回合，普通行动不会重新增加时间。断线保留 45 秒重连时间，开始后主动离开视为认输。双方同时离线导致超时的棋局不计分。旧连接不能在已被新会话替换后继续修改房间或行动。服务器重启会清空正在等待或进行的房间；已结算段位保留。

## 星图位阶

| 位阶 | 积分起点 | 意象 |
| --- | --- | --- |
| 微光旅人 | 初始 1000，最低 0 | 让第一颗星亮起 |
| 翠枝行者 | 1050 | 每一步都生出新的枝叶 |
| 赤曜先锋 | 1200 | 在交锋中寻找自己的光 |
| 星辉策士 | 1400 | 让远星连成棋局 |
| 王庭执棋者 | 1650 | 胜负之外，仍有推演 |
| 天穹织星者 | 1900 | 以整片星空回应下一手 |

首五场为定轨局，采用 Elo 预期胜率与 K=48；之后 K=32。胜负与对手积分共同决定变化，不靠连胜倍率堆积。同一对手在北京时间同一自然日的前三场计分，后续仅保留对局记录。休闲、练习与战役不计分，位阶不提供战斗属性。

棋风星图以已结算计分排位中的有效操作统计「强攻 / 机动 / 咏法」比例，分别对应普攻、移动和主动施法/技能卡。它是操作记录，不是胜率、伤害或玩家能力测评。个人档案显示位阶路线和最近 20 场排位。

当前身份是服务器登记的设备访客身份，凭据按服务器地址隔离保存在浏览器。服务端只保存凭据摘要，积分由服务端结算并持久化；换浏览器或清除浏览器数据后不会自动找回原设备身份。正式账号互通仍需绑定平台登录，不能把目前的访客体系宣传为已接入 TapTap 账号系统。

## 练习模式

- 初识：电脑走位、普攻，不主动施放角色技能。
- 标准：电脑使用完整角色技能并做远程拉扯。
- 谋略：增加手牌使用时机与低血量移动威胁评估。

三个难度使用相同基础属性，区别在决策。快速上场提供均衡、召唤、棋阵三套预设；选卡推演保留完整三选一、部署与对局流程。电脑负责自己的选卡和部署，玩家不能代替电脑操作。练习无金币、战役或段位奖励。

## 本机启动与连接诊断

安装 Node.js 后双击根目录「启动游戏.cmd」，或在 H5 目录执行 `npm start`。检测到同端口旧版服务时会提示关闭旧启动窗口，避免新版大厅误连旧协议。

```powershell
node tools/probe-server.cjs http://服务器IP:8080
node tools/probe-server.cjs https://你的域名/tactics
```

诊断只读取健康状态、WebSocket 回应和公共房间列表，不创建账户或房间。HTTPS 页面必须使用有效证书的 WSS；不使用证书跳过选项。

## Linux 服务部署清单

联机服务 ZIP 包含网页、规则、房间服务、ws 依赖与部署示例，不包含 Node.js。上传后解压至独立目录，例如 `/opt/tactics/releases/0.8.13`，并让 `/opt/tactics/current` 指向该目录。保留旧目录可回滚。

1. 先检查已有进程、监听端口和 nginx 配置，避免覆盖现有网站或代理服务。
2. 安装 Node.js，建立无登录权限的 `tactics` 服务用户；创建并授予其 `/var/lib/tactics` 写权限。
3. 参考 `server/tactics.service.example` 设置 systemd。示例监听本机 `127.0.0.1:8088`，段位文件保存在 `/var/lib/tactics/players.json`，与发布目录分离。
4. 把 `server/tactics-location.conf.example` 的 location 加入目标站点的 nginx server 块，运行 `nginx -t` 后重载。它使用 `/tactics/` 前缀，转发 WebSocket；保留其他路径和 TLS 配置。
5. 先从服务器本机验证 `http://127.0.0.1:8088/health`，再从外部运行上面的诊断工具，最后用两名玩家实际建房、准备、选卡和对战。

普通直连测试可使用 `PORT=8080`；生产反向代理建议仅监听本机地址。部署示例中的 `/usr/bin/node` 必须匹配服务器上的实际 Node 路径。段位 JSON 适合目前的单实例试玩服务；不可用多个服务进程同时写同一文件。私有数据不通过静态路由暴露，也不会进入发布包。

## 验证与美术

规则测试覆盖公共房间、房主权限、双方准备、回合权限、身份校验、段位持久化及幂等结算。浏览器加独立 WebSocket 玩家完成真实建房、加入、完整选卡部署、双方回合、休闲与排位结算，并验证人机离线流程。手机与桌面布局分别验证。

大厅、练习场和徽章由image_gen绘制：运行图位于 `assets/backgrounds/lobby-observatory-v1.webp`、`assets/backgrounds/practice-courtyard-v1.webp`、`assets/icons/star-rank-v1.webp`。原始大图不随公开仓库发布。动态星图由SVG展示真实操作比例。
